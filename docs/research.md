# Исследования

Данные: рабочий корпус прототипа, 2–4 октября 2026 года. Эталоном служат ответы LLM, а не экспертная разметка.

## 1. Где тратится время

Ночной прогон разметки: 577 публикаций, 1361 запрос к модели за два прохода.

| Этап | Время | Доля |
|---|---|---|
| Ожидание ответа LLM | 301,7 из 301,8 мин (первый проход) | 99,97 % |
| Проверка, JSON, запись в SQLite между запросами | ~0,01 с на запрос | < 0,1 % |
| Снимок корпуса | ~6,5 с | — |
| Сборка выпуска | ~2 с | — |
| Опрос одного источника | 0,4–1 с | — |

Почему LLM-этап долгий:
1. **Запросы идут последовательно:** два на публикацию, классификация и извлечение.
2. **Задержка определяется длиной ответа:** корреляция с числом выходных токенов 0,76, с входными — 0,39. Скорость модели ~110–140 токенов/с.
   - медиана ответа классификации — ~1400 токенов, хотя нужен короткий JSON;
   - медиана ответа извлечения — ~2900 токенов.
3. **Вход почти целиком служебный.** Медиана текста публикации — 192 символа, а вход — ~3000 токенов: системный промпт и JSON-схема.
4. **101 из 560 запросов на извлечение вернул «недостаточно содержания».** На каждый ушло ~20 с.

**Прогноз:** время ≈ число новых публикаций × ~42 с + ~10 с.

| Сценарий | Время |
|---|---|
| Ежедневный выпуск при потоке 1–5 новых публикаций | 1–4 мин |
| Месячный выпуск, если ежедневные прогоны шли (всё в кэше) | секунды |
| Первичная загрузка архива из 577 публикаций | ~6,7 ч |

**Что ускоряет:**
- анализировать только свежие публикации;
- отправлять запросы параллельно;
- отсекать короткие тексты до запроса к модели;
- запрашивать извлечение только для кандидатов в выпуск — так устроен гибридный режим.

## 2. Правила, локальный классификатор и LLM

Сравнение с ответами LLM на 577 публикациях.

| | Основная тема: точность / macro-F1 | Тип события: точность / macro-F1 |
|---|---|---|
| Самый частый класс | 0,42 | 0,41 |
| Словарные правила | 0,28 / 0,13 | 0,04 / 0,04 |
| TF-IDF + логистическая регрессия, 5-кратная CV | **0,77 / 0,54** | **0,82 / 0,70** |

- **Правила.** Сильно уступают и пропустили бы дальше вдвое меньше публикаций, чем LLM. Главная причина — словари не покрывают русскоязычные тексты по промышленной безопасности.
- **Классификатор.** Повторяет LLM на крупных классах (уязвимости — F1 0,94, выпуски продуктов — 0,86) и слаб на классах с 10–16 примерами. Обучение и разметка всего корпуса занимают ~5–7 с против ~2,5 ч у LLM.

## 3. Перенос между источниками

Три рубрики датасета («Атака», «Уязвимость», «Инфо»), 896 публикаций из 32 источников, пять разбиений.

| Модель | Macro-F1, разбиение по событиям | Macro-F1, разбиение по источникам |
|---|---|---|
| TF-IDF → логистическая регрессия | 0,830 | 0,274 |
| TF-IDF → LinearSVC | 0,823 | 0,274 |
| Multilingual MiniLM → логистическая регрессия | 0,764 | 0,399 |

При разбиении по событиям классификатор выглядит сильным. Но на источниках, которых не было в обучении, TF-IDF почти теряет рубрики «Атака» и «Уязвимость». Энкодер переносится лучше, однако требует ~1,4 ГБ RAM и тоже недостаточен для самостоятельного решения.

**Вывод:** локальная модель экономит запросы на частых и уверенных случаях, а LLM и проверяемые правила остаются запасным путём.

## 4. Устойчивость проверки цитат

В первой версии одна неподтверждённая цитата отклоняла всю публикацию, хотя обычно подтверждались 3 из 4–5 цитат. После перехода к частичной отбраковке все 8 публикаций, отклонённых по этой причине на тестовом корпусе из 40, прошли проверку с подтверждёнными утверждениями. Непрошедшие цитаты записываются в журнал для разбора.
