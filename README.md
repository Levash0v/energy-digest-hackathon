# SOC-дайджест · кейс команды «Трюфель»

[English version](README.en.md)

ИИ-ассистент, который собирает публикации по ИТ и информационной безопасности, отбирает их под интересы читателя и выпускает тематический дайджест с дословными цитатами и ссылками на первоисточники.

Прототип сделан для полуфинала хакатона «ИИ-ассистенты для энергетики», задача «Ассистент для создания ИТ/ИБ-дайджестов», октябрь 2026.

> В репозитории описание решения, архитектура, исследования и примеры результатов. Исходного кода сборщиков, парсеров и конвейера здесь нет.

![Ежедневный выпуск для технических специалистов](screenshots/digest-tech.png)

## Что делает

- **Два выпуска для двух аудиторий:**
  - ежедневный для технических специалистов, окно 08:00–08:00 МСК;
  - ежемесячная сводка для руководства за прошлый календарный месяц.
- **Отбор под интересы:**
  - профиль аудитории: веса тем, исключения, список отслеживаемых классов продуктов;
  - инвентарь «наших» продуктов и версий: «касается ли нас»;
  - приоритеты P1–P3 с сохранённой причиной решения.
- **Группировка:**
  - публикации об одном событии объединяются, все источники сохраняются;
  - выпуск разбит на разделы («Атака», «Уязвимость», «Инфо» и др.) и открывается блоком «Главное».
- **Проверяемость.** Каждое утверждение в карточке опирается на дословную цитату из исходной публикации. Цитата, которой нет в тексте источника, отбрасывается. Утверждение без подтверждённой цитаты в выпуск не попадает.
- **Форматы:** веб-страница, Markdown, HTML, JSON (контракт [`issue_v1`](schemas/issue_v1.json)), DOCX.

## Результаты на рабочем корпусе

Снимок от 3–4 октября 2026 года. Это объём и поведение системы, а не оценка точности на экспертной разметке.

| Показатель | Значение |
|---|---|
| Публикаций в корпусе | 896 из 77 источников (сайты, Telegram-каналы, CISA KEV) |
| Первичная LLM-разметка | 577 публикаций, около 7 ч последовательной обработки |
| Ежедневный технический выпуск | 564 публикации → 563 события → 459 подходящих → **14 карточек** |
| Ежемесячная сводка для руководства | 33 подходящих события → **8 карточек** |
| Где тратится время | 99,97 % — ожидание ответа LLM; сбор, проверка и сохранение < 0,1 % |
| Стоимость одной новой публикации | ~40–46 с LLM-времени (классификация + извлечение) |

Подробности: [исследования](docs/research.md).

## Стек

Python 3.12, pydantic, httpx, SQLite, FastAPI, статический фронтенд (HTML/CSS/JS), scikit-learn. LLM подключается через OpenAI-совместимый API или нативный протокол Ollama. Модель задаётся алиасом в конфигурации и меняется без переделки кода. В исследованиях использовались Claude Haiku 4.5 и GLM-5.3-flash.

## Ограничения

- Качество на экспертной разметке не измерено: локальный классификатор обучен на слабых метках — ответах LLM.
- Корпус перекошен: 496 из 577 размеченных публикаций — один источник.
- Конвейер обрабатывает публикации последовательно; первичная загрузка большого архива занимает часы.
- Проверка цитаты подтверждает, что фрагмент есть в источнике, но не подтверждает смысл утверждения.
- Экономия времени экспертов не измерена.
